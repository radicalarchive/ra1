## 2026-08-13 18:30 — decompilation, seams, first five classes

- **Procyon cannot be pointed at a directory of classes** — `-o out/ <dir>` gives "Failed to load class <dir>". Run it once per `.class` file.
- **13 of 14 game classes recompile clean** under `javac -source 8 -target 8`. The only artifact is `F51$1.java` ("modifier static not allowed here"), procyon's rendering of an anonymous `WindowAdapter` — 12 lines, the window-close handler.
- **`sun/audio/` inside the jar is a vendored copy of the JDK's own package**, bundled because Java 9 removed it. Not game code; the port drops it.
- **`ra1.jar` runs unpatched on JDK 17.** Unlike nfm's `Game.jar`, which needed seven bytecode patches, this build already works — the vendored `sun.audio` is why.
- **The drawing surface is eleven methods** (`setColor drawImage fillRect drawString fillPolygon drawRect drawLine drawPolygon setFont getFontMetrics dispose`) plus `PixelGrabber`/`MemoryImageSource`/`createImage`. nfm's was 42.
- **The menus round-trip the whole framebuffer through JS every frame** — `xtGraphics.drawefimg/drawpimg/drawop/drawl/drawovimg/cmback` do `new Color(pix[i])` over 180,000 pixels and blend against a stored JPEG. That, plus the 500×360 frame, is why `port/graphics.js` is Canvas2D and not WebGL: the effect is a `getImageData` here and a `readPixels` stall there.
- **`SinCos.getsin`/`getcos` return `float`**, so every expression that touches them is float32 in Java and needs `fr()` at each binary operation. Essentially every coordinate in this game passes through them. Same hazard as nfm's `Medium.sin`/`cos`.
- **`java.awt.Color`'s int constructor throws outside 0..255**, and the game clamps by hand before every construction. `colorOf()` in `port/java.js` throws too, deliberately — a silently clamping port would hide a real divergence.
- **`DataInputStream.readLine()` is Latin-1, not UTF-8.** That is why it is deprecated in Java. Decoding the `.rad`/`.txt` files as UTF-8 would turn a stray high byte into U+FFFD and corrupt a model silently.
- **The game's loaders are synchronous inside `F51.run()`**, so `port/vfs.js` preloads every asset at boot and serves reads synchronously. Making them async would infect the main loop and stop the transpilation being line-by-line.

### Delegating to `agy`

- **`agy -p` cannot run shell commands headlessly.** It auto-denies anything needing the "command" permission and says to add an allow-rule or pass `--dangerously-skip-permissions`. Both are blanket grants over the whole machine, so this port does not use them: the subagent gets Read and Write, and the caller compiles and runs every probe. See the header of `decompilation/agy_ra1`.
- **File writes DO work headlessly** with no flag and no config change, including outside a trusted workspace (`allowNonWorkspaceAccess: true` is already set globally). Only commands are blocked. Verified by writing a file into `port/tools/`.
- **`--effort` is rejected for `claude-*` models** ("--effort is not supported for model claude-sonnet-4-6"), not just for the `-thinking`/`-high`/`-low` variants. The wrapper drops the flag for all of them.
- **`agy` is Google's Antigravity CLI** (`jetski` internally); its config lives at `~/.gemini/antigravity-cli/settings.json`.
- **Calibration result, SinCos:** the `port` → probe → `test` loop produced a clean class and 12 passing probe-derived tests on the first attempt, with no template changes.
- **Calibration result, Plane:** transpilation was faithful, `rot()`'s per-operation `fr()` was right, and all four §2 compound-assignment sites were classified correctly (verified against `javap`: `d2i; iadd; putfield` at 502 and 391, and `imul; iadd; i2d; sqrt; d2i; iadd` at 2626-2646 — all Case B). Two systematic misses, both now folded into the template: **`int[]` allocated as `new Array(n).fill(0)` instead of `intArray(n)`**, which silently loses wrap-on-store, and **`(a * b) / c` in `xs`/`ys` left as a plain JS multiply** where the bytecode is `imul; idiv; iadd` and the product overflows for far vertices. The subagent flagged the array-typing gap itself in its report, which is the delegation contract working.
- **The reference jar cannot be run inside this sandbox.** `java -jar ra1.jar` under `xvfb-run` dies with `UnsatisfiedLinkError: libawt_xawt.so`, so no reference screenshots from an agent session — the user has to capture those. Headless AWT still works, which is all the probes need (`BufferedImage.createGraphics()` under `-Djava.awt.headless=true`).
- **The distribution is missing `siters/clmap1.txt`, `clmap2.txt` and `clmap4.txt`.** `F51.run()` loads `"clmap" + (int)(Math.random() * 5.0)`, and `loadobjects` swallows the FileNotFoundException — so on three runs in five the cloud layer is simply absent in the original game. Reproduce it; do not "fix" it by pointing the missing indices at clmap0 (§3).
- **Java's implicit array bounds check is load-bearing in the model parser.** `Plane`'s constructor walks indices 0..2 whatever the face's vertex count is, and `graphics/bebs.rad` has two 2-vertex faces — so Java throws, `ContO`'s `catch (Exception ex) {}` abandons the rest of the file, and the real model has **6** faces, not the 8 in the file. The port must read through `at()` (java.js) at any site where the loop bound and the array length come from different places. Without it the port built two extra NaN faces and every test still passed; only a probe over all 56 `.rad`/`.dar` files caught it.
- **`ContO.getvalue` throws in ordinary use, and the game depends on it.** Probed: `getvalue("colid", "colid(3)", 1)` throws StringIndexOutOfBounds because `++j` walks off the end after the `)`. `charAt`/`parseIntJava` in java.js reproduce it; JS's own `charAt` returns `""` and would parse more of the file than the original does.
- **The `agy` quota is per-subscription and runs out.** It died mid-job after ~6 jobs with "Individual quota reached… Resets in 4h29m". A job that hits it exits 0 having written only part of its output — check the files, not the exit code.
- **A differential test that passes is not evidence until you mutate the rule it protects.** `Medium`'s nine §2 sites are Case A; the first test drove all seven view modes for eight steps each, passed, and **still passed with every site flipped to Case B**. The two rules differ only when the accumulator is positive and the step is a small negative fraction (`trunc(5000 - 0.67)` = 4999 vs `5000 + trunc(-0.67)` = 5000), which needs the camera CONVERGING DOWNWARD onto a positive target — a case the game's default camera position never reaches in eight steps. After adding those four cases the mutation fails three tests. **Mutate the site, re-run, confirm red, revert.** Cheap, and the only way to know the assertion has teeth.
- **Medium carries this port's first §2 Case A sites** (Plane's four were all Case B): `x/y/z += (int)(expr / 1.5)`, verified as `getfield ; i2d ; … ; ddiv ; dadd ; d2i ; putfield`. Note the asymmetry in `right()` — its `x` uses an int `/3` while `left()` uses `/1.5`; that is what the bytecode says, and it is presumably the author's slip. Keep it (§3).

## 2026-08-13 22:15 — finished F51.js

- **`F51.js` is finished**: all seam methods (`init`, `start`, `stop`, `destroy`, `downloadall`, `playsounds`, `getImage`, `getSound`, `open`, `run`) are implemented without touching existing methods or modifying other `.js` files.
- **Main loop / threading model**: `run()` is `async run()`, loop condition driven by `this.gamer`, yielding via `await new Promise((r) => requestAnimationFrame(r))` instead of `Thread.sleep`. Pacer arithmetic (`f`/`f2` ±0.5 in-flight, ±3.5 in-menus floored at 5.0) and time window delta calculation (`l8 - l3 < 560L` / `400L`) preserved with `Date.now()`.
- **Preloading contract**: `init(canvas)` preloads VFS files, base models zip, graphics images into a Map, and audio clips into a Map so that `getImage(s)` and `getSound(s)` can return synchronously within `downloadall()` and `run()`.
- **Painter's algorithm invariant (§4)**: `ContO` depth-sort and polygon draw submission order in `run()` preserved exactly without batching, hoisting, or reordering.
- **Verification**: all 129 existing unit/differential tests pass; `node -e "import('/home/evan/resources/ra1/port/F51.js').then(()=>console.log('OK'))"` succeeds.

- **THE PORT BOOTS AND RUNS.** `F51.run()`, the seams and `port/main.js` are in; the game loads its models, plays the intro, renders the title scene with real 3D models, and takes keyboard and mouse input in Chromium. Serve the repo root and open `port/main.html`.
- **The delegated `run()` computed the frame delay and then threw it away.** It kept Java's adaptive pacer arithmetic (`l9 = round(f) - elapsed`) and then awaited a single `requestAnimationFrame`, i.e. 16.7ms regardless — every physics step in this engine is per-frame, so a race would have run ~3.4× too fast. The fix is to yield frames until `l9` ms have actually elapsed. Measured after the fix: **25.8 game iterations/sec in the menus**, against Java's 400ms-per-10-frames target. Nothing in the test suite could have caught this.
- **`chromium --headless --screenshot` cannot smoke-test this port.** That mode drives the page with VIRTUAL time, which does not advance across `createImageBitmap` or `decodeAudioData`: the boot appears to hang for exactly the `--virtual-time-budget` and then completes the instant it expires, which is indistinguishable from a real deadlock. `port/tools/smoke.mjs` drives the DevTools protocol over a real clock instead — console, page errors, canvas non-blank count, game-loop rate, and screenshots before and after a click.
- **Asset paths must resolve against `import.meta.url`, not the page.** The job wrote `vfs.setFpath('../')`, which is right only for a page in `port/`; any harness one directory deeper 404s on every asset. `const REPO = new URL('../', import.meta.url).href`.
- **The job preloaded `sounds/newsun/*.wav`, which do not exist** — that directory ships `.au` files, and the `newsun` branch is dead code (`"".startsWith("sun.")`). Sixteen 404s at boot, swallowed by a `try/catch` that also hid real failures. Images now throw on a miss; sound failures are collected and warned about, since the game is playable silent.
- **2× resolution is a context transform, not a coordinate change.** `Graphics2D` takes a `scale`, sets `ctx.setTransform(2,0,0,2,0,0)` and the game's 500×360 coordinates are untouched, so no transpiled line changes. The one thing that cannot follow is the pixel effects: `drawop`/`cmback` walk a 500×360 `int[]` by construction, so `grabPixels` resamples the bigger surface down to 500×360 and the effect lands upscaled.
- **Careful measuring the tick rate once interpolation exists.** `smoke.mjs` counts `F51.repaint()`, which is called once per loop-body run — with interpolated frames re-running the body that counts DRAWS, not ticks. Count the simulation separately, or a working feature looks like a 3× speedup and a broken one looks correct.
- **Smooth motion (interpolated frames) is in, following nfm's design**: physics ticks unchanged, `medium.interpolating` guards every draw-time mutation at the mutation, draw-time randoms are recorded on the tick and replayed on interpolated frames, and `ContO.dist` is snapshotted because it feeds the next depth sort. Angles blend shortest-path and stay FRACTIONAL — `SinCos.getsin/getcos` now lerp between table entries for a non-integer argument (integer arguments still hit the table exactly, so every probe-verified value is untouched).
- **An interpolated pass must replace the tick's draw, not follow it.** The delegated version drew the tick (state N) and then redrew blends of N-1→N across the same window, so every tick visibly rewound. `Graphics2D.mute` now suppresses the tick's rasterisation under smooth motion — the geometry still runs, because it computes `ContO.dist` — and the interpolated passes are what reaches the screen. Costs one tick of display latency; nfm reached the same conclusion ("when interpolating, NO tick draws").
- **A muted tick must be followed by at least one drawn frame.** If the display's frame lands outside the sleep window the do-loop can exit having drawn nothing, freezing the screen for a whole tick. There is now a `t = 1` fallback pass.
- **The random replay log must be Float64.** The job wrote `Float32Array`, which quantises every replayed value — the exact shimmer the replay exists to remove.
- **How to test the guards: force the interpolation rate, don't wait for the display.** `f._forceInterp = N` runs N interpolated passes per tick regardless of timing (`SMOKE_FORCE_INTERP=4`). Measured at a 10× draw rate, the per-tick advance of xtGraphics' counters is unchanged — which is the property the guards exist to hold, and it is invisible at the ~1.4 interpolated frames per tick a headless browser actually produces.
- **Counter deltas are a trap as an equivalence probe.** `cntf` is reset to `random()*150` on a wrap and `cnts` wraps at -900, so their per-second deltas say nothing about rate; and a probe that reads -1 in both samples differs by 0, which looks exactly like "nothing advanced". Print absolute values alongside deltas.
